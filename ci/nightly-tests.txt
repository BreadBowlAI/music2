# ci/nightly-tests.txt: the Rust tests that run only in the nightly tier, each with why.
#
# In short: the PR tier (ci/pr.sh rust, and so every pull request) leaves these out; the nightly tier
# (ci/check.sh, which runs every test) still runs them, unchanged. A test is here for one of three
# reasons, and only these:
#   speed     it judges how FAST something happens (a bound under 2 s, or a real-time period), so a
#             slow or busy machine fails it with correct code. A test that only waits up to a
#             deadline of 2 s or more for something to happen stays in the PR tier: it fails only
#             if the thing never happens.
#   flake     it failed on correct code in a recorded run (HANDOFF.md's "Known flakes", or the
#             open-source audit of 2026-10-21) and the cause isn't fixed yet.
#   slow      it alone takes over a minute on 4 cores ("run the expensive tests nightly").
# A test here is never weakened or deleted to get it back: fix the cause (a flake), make it
# measure work instead of time (speed), or make it quicker (slow); then take its line out.
#
# One line a test: <nextest binary id> <test name> <reason...>. The binary id is the package, or
# package::<file> for a file under tests/ (cargo nextest list prints them). Test names must match
# exactly: the "nightly list" row (ci/pr.sh rust, ci/check.sh) fails on a name nextest can't find.
# ci/pr.sh turns these lines into a nextest filter (ci/nightly-list.sh): ci/pr.sh rust leaves them
# out, and ci/pr.sh rust --all runs them too. To run one alone (cargo-nextest from ci/tools.sh):
#   cargo nextest run --locked -E 'binary_id(=<binary id>) & test(=<test name>)'
