# m2 commands

**In short**
- Every `m2` command, with what it does.
- `m2` works on song folders, with the app open or closed.

`m2` works on song folders, with the app open or closed. Build it once with `cargo build --locked --release -p m2`. The program is `target/release/m2`; the examples below call it `m2`. It finds std, the templates and the examples the way the app does: at `$M2_STD`, `$M2_TEMPLATES` and `$M2_EXAMPLES`, else in this source tree.

| Command | What it does |
|---|---|
| `m2 new <folder>` | Makes a new song in exactly that folder (it refuses one that exists) from a template: `--template starter` (the default) or `--template empty`. `--example first-song` copies an example instead. |
| `m2 check <song> [--json]` | Runs the code and checks the graph and the timeline. `--json` prints the compiled graph. `m2 build` is the same. |
| `m2 render <song> <out.wav>` | Renders the song to a 24-bit WAV, the same file the app's Export (Song) writes: to the end of the last clip, then on until the sound has been silent for half a second (10 s past the end at most). It renders at the song's `sample_rate`, from `music2.toml`. `--from S` starts S seconds in (or `--from-bar N` at bar N, counted from 1), replaying the song up to there; `--seconds N` renders exactly N seconds. 3 hours at most. `--preroll P` starts only P seconds before instead of replaying: much faster late in a long song, for listening, but approximate, as it says (notes held from before then, and earlier tails, are missing), and never written into `assets/`. `--threads N` renders on N threads, the same file on any number. If a part breaks while it renders, it fails and names it. |
| `m2 kernels [--json]` | Every kernel and its typed ports. |
| `m2 bounce <song> <name>` | Renders a track, named by its key (`--track keys`), or the whole song to a new `assets/<name>.wav`; it never replaces one that's there. `--place keys.lane@beat` also puts it on an audio lane. |
| `m2 graph <song> [--json]` | The graph the app shows, as text. |
| `m2 controls <song>` | Every number the app can turn into a knob, with its id, including the controls a call leaves out (`tracks/hats.ts#1/@decay`, marked inherited). |
| `m2 set <song> <id> <value>` | Changes one, checked by the compiler. `--expect V` refuses unless it's V now. |
| `m2 automate <song> <id>` | Gives a knob an automation lane of its own, as the app's Automate does: the knob's number becomes the lane's fallback, so the song sounds the same. |
| `m2 label <song> <track> <name>` | Shows a track, named by its key, as `<name>`: only its `track()` call's name changes. |
| `m2 import <song> <file.wav>… [--track key] [--at bar]` | Brings WAV files into `assets/` and places their clips: on a track's audio lane, or each on a new audio track, as one checked edit. With the song open in the app, the app brings them in, as one undo step, and nothing is copied while you hold the song (a take, V's Compare): it waits, as every write does. |
| `m2 mute-in-song <song> <track>… on\|off` | Mutes tracks in the song (every render and export), or unmutes them. |
| `m2 clips <song> <gesture> <clip>…` | One clip edit: `create`, `move`, `resize`, `split`, `join`, `duplicate`, `quantize`, `delete`. A clip is `track/lane:id` or `track/lane@9.3.1` (where it starts). `m2 clips <song> json <gesture.json \| ->` takes any gesture `POST /api/graph/clips` takes, as JSON: also `paste`, `notes`, `points`, `audio` and `set`. |
| `m2 unautomate <song> <track>/<lane> [--at place]` | Takes a knob's automation out: the lane's value there goes back into the code. |
| `m2 add-track <song> <instrument>` | Adds a track playing an instrument (`synth.pluck` or `std:synth-pluck`), as + Track does. `--name "Lead Vox"` names it, `--key` gives its key, `--after kick` puts it below that track. |
| `m2 duplicate-track <song> <track>` | Copies a track, named by its key: its code, its clips (with new ids), its plugins' saved settings and its mixer channel. |
| `m2 delete-track <song> <track> [--cascade]` | Takes a track out: its file, its imports, its channel, its data and its place in `layout.json`. When an effect elsewhere listens to it (a duck), it lists them and changes nothing; `--cascade` takes the track out of them too. |
| `m2 layout <song> order <keys…>` / `colour <key> <colour>` / `reset` | Reorders or recolours tracks in `layout.json` (rose, teal, amber, indigo, green, plum, olive, blue, coral, cyan, violet, lime), or writes the default layout over one that doesn't read. No revision: the layout never changes the sound. |
| `m2 tempo <song> <bpm> [--at <bar>]` | Sets the song's tempo (20 to 999 BPM) in `data/arrangement.json`, or with `--at 9` a tempo change from bar 9. |
| `m2 meter <song> <n/d> [--at <bar>]` | Sets the song's time signature (`7/8`: 1 to 64 beats of a 1, 2, 4, 8, 16 or 32 note), or with `--at 9` a change from bar 9. |
| `m2 title <song> <name>` | Renames the song: its name in `music2.toml`. The folder keeps its own. |
| `m2 cables <song>` | The named signals a cable can start from, and the inputs that cables reach. |
| `m2 connect <song> <signal> <control>` | Writes a signal's name in place of a number. |
| `m2 disconnect <song> <input>` | Writes the input's default back in place of the name. |
| `m2 effects <song>` | The effects packages offer, by id (`std:delay`), and the calls they can go after. |
| `m2 add-effect <song> <call> <effect>` | Wraps a call's sound in an effect, named by its id (`std:delay`) or where it's exported (`std/fx.delay`). |
| `m2 remove-effect <song> <call>` | Takes an effect out, keeping what it was applied to. |
| `m2 plugins [clap:<id>]` | Installed CLAP plugins, or one plugin's ports. |
| `m2 plugin-state <song> <track>/<key> clap:<id>` | Saves a plugin's default settings as its saved state. |
| `m2 relink <song> <from> <to>` | Moves data no lane or plugin reads to where it's read now, after a key was renamed in code: a track's folder (`data/kick data/kicks`), a lane file (`data/kick/hits.json data/kick/beats.json`) or a plugin's state. |
| `m2 delete-data <song> <path>` | Deletes data no lane or plugin reads. |
| `m2 fix <song> <path> <fix>` | Applies a fix a problem offers, such as `assign-clip-ids` or `repin-asset`, or `finish-tx` and `discard-tx` for an edit that was cut off (its path is `.music2/tx/<id>.json`). Every command prints the problems it finds with the commands that fix them. |
| `m2 tx <song> <tx.json \| -> [--check] [--seen HASH]` | A checked edit written as Tx JSON (see [Scripts and agents](api.md)). `--check` prints what it would change and that change's hash, writing nothing; without it, it is written, and `--seen HASH` writes it only while it still makes the change with that hash. The answer is JSON; the exit status is 1 when nothing was written. |
| `m2 edit <song> <file> --old <text> --new <text> [--all]` | Replaces text found exactly once in a text file of the song (every time, with `--all`), as one checked edit. Found no times, or more than once without `--all`, it changes nothing and says how many times. If the file changed after it was read, it reads it again and tries once more. While the song's code doesn't build, it fixes a code file: it saves it as the app's code editor does, and only if the song then builds; otherwise it changes nothing and prints the errors. |
| `m2 write <song> <file> [<from> \| -]` | Writes a whole text file of the song (a new track's file, a rewrite), from a file or standard input, as one checked edit. It writes text only: `m2 import` brings audio in, `m2 plugin-state` saves a plugin's state. While the song's code doesn't build, it fixes a code file that is there, as `m2 edit` does. |
| `m2 undo <song> [--as name]` | Takes back your own newest change in the open app: only while the newest change is yours, by name, never the musician's or another agent's (it says whose it is). With the app closed there is nothing to undo: undo lives in the open app. |
| `m2 focus <song>` | What the musician looks at in the open app, as JSON: the dock's view, the selected track by its key, the clips picked (`{track, lane, id}`) and a marquee's bars (`range`), the roll's selected notes by `pitch`, `start` and `length`, the knob last touched, the beats the timeline shows (`seen`), the code view's file and line; and from the app, `playing`, `beat`, `loop`, the files with unsaved code, what V compares (`comparing`) and the MIDI keyboard's target (`midi`). Fields the window hasn't said yet are null. It writes nothing. |
| `m2 watch <song> [--meters]` | Follows that song in the open app: first `{"t":"watch","session":…}`, then each event its window hears, one JSON object a line with `t` first and the song's `session` (a change landed, an undo or a redo, a toast, the focus, a pointer, the Compare pill; below), and `transport` when it plays or stops, the loop changes or the playhead jumps (read every quarter second). The meters only with `--meters`. When the app quits it prints `{"t":"closed","why":"app"}` and exits 0; when the app opens another song or closes this one, `{"t":"closed","why":"song"}`, and it prints nothing of the other song. While whoever reads it doesn't, it keeps 1,024 lines and drops the rest, then says `{"t":"lagged","missed":n,"by":"m2"}`; when they go away (`m2 watch … \| head -1`), it ends quietly. It writes nothing, and it never takes a message from the musician's window. |
| `m2 point <song> <target> "<words>"` | Shows a note in the open app at `track:bass`, `clip:bass/notes:<id>`, `lane:bass/cutoff`, `knob:<id>` (as `m2 controls` names it) or `bars:9-16` (or `bars:9`), by your name (`--as`): how an agent says "listen to bars 9 to 16"; the musician presses play. It never moves their view or selects. `--clear` takes it away; so does their OK. A target the song hasn't is refused, saying so, and so are bars past its end, saying how many bars it has. |
| `m2 listen <song> [--bars 9-16] [--tracks kick,bass] [--as-heard] [--with tx.json] [--png out.png] [--json]` | Measures the song, for an agent that can't hear it ([Listening](listening.md)): the mix and each track's loudness, true peak and crest, their octave bands, stereo and masking. The bars count from 1; without `--bars`, the loop when one is on, else the whole song. It writes nothing into the song, works with the app open or closed, and runs one at a time, at background priority. |
| `m2 routes [--json]` | Every route of the app's API, from its one route table: the ones agents may call first, each with what it does, whether it writes and an example body, then the musician's own. `--json` prints the table: `[{method, path, limit, writes, agents, words, example}]`, `limit` being the largest body the route takes (2 MiB, more for imports and Tx). No app needs to run. |
| `m2 call <song> <path> [<json> \| -] [--method M]` | Sends one route's request to the app that has the song open, as an agent (`--as`, `--why`): how to reach a song change with no command of its own (an effect turned off, markers, the song's key, a track's instrument or ID, a bus) or any read. The song's `session` is filled in when the body leaves it out, and a GET's keys go in its query; `--method` picks one where a path takes two (`/api/settings`). It prints the app's answer, as JSON, and exits 1 when the app refuses it; a write the musician holds waits, as every `m2` write does (exit 3). The musician's own controls, and a body bigger than the route takes, are refused before anything is sent. On standard error it says the undo step a write made, or what an undo took back. |
